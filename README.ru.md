# jobwatch v5

Каждое утро по будням собирает удалённые вакансии с семи бордов, отсекает то, что вам не подходит, сортирует по релевантности и присылает в Telegram 8 лучших. Для самых сильных готовит черновик письма.

## Новое в v5

- **Отметки из Telegram.** У каждой вакансии в дайджесте есть номер. Откликнулись — ответьте боту «+105». Статусы: «ответ 105», «интервью 105», «оффер 105», «отказ 105». Статистика — /stats, справка — /help. Бот проверяет сообщения каждые 3 часа и отвечает подтверждением. Команды принимаются только из вашего чата.
- **Напоминания о follow-up.** Если через 7 дней после отклика нет ответа, бот один раз напомнит и пришлёт шаблон письма рекрутеру.
- **hh.ru.** Удалённые вакансии по русским и английским запросам, зарплата в рублях в месяц, свой порог (по умолчанию от 110 тысяч), бонус русскоязычным вакансиям.
- **Ещё три системы найма** для карьерных страниц: Recruitee, Personio, SmartRecruiters — на них сидит много европейских компаний.
- **Прямые ссылки в приоритете:** если вакансия пришла и с агрегатора, и с сайта компании, в дайджесте будет ссылка на сайт.

## Трекер: два файла

- `tracker.csv` — правите вы вручную, как раньше.
- `tracker_tg.csv` — сюда бот записывает отметки из Telegram. Руками не трогайте.

Бот читает оба. Так ваши правки на GitHub и его коммиты не конфликтуют.

## Новое в v4

- **Карьерные страницы компаний.** Добавьте в `config.toml` компании, которые вам интересны, и бот будет забирать их вакансии напрямую с Greenhouse, Lever или Ashby. Такие вакансии помечены ◆ и получают бонус к баллу. Это автоматизирует еженедельный ручной обход career-страниц.
- **Поиск по границам слов.** Раньше стоп-слово «intern» выкидывало International и Internal, «sales» — Sales Engineer, а «iam» срабатывало внутри других слов. Исправлено.
- **HTML-сущности раскодируются** — «REST&nbsp;API» теперь распознаётся как навык.
- **Контроль источников.** Если агрегатор три запуска подряд возвращает ошибку или ноль — придёт предупреждение. Если не ответил вообще никто — предупреждение сразу.
- **Строка для tracker.csv** в шапке каждого черновика — копируете и вставляете.
- **Не больше двух вакансий от одной компании** в Telegram-дайджесте.
- **Старые черновики удаляются** через 30 дней.
- **Тесты** запускаются перед каждым сбором; если после правки конфига что-то сломалось, запуск упадёт, и GitHub пришлёт письмо.

## Как добавить карьерные страницы

Откройте страницу вакансий компании и посмотрите на адрес:

- `boards.greenhouse.io/slug` или `job-boards.greenhouse.io/slug` → greenhouse
- `jobs.lever.co/slug` → lever
- `jobs.ashbyhq.com/slug` → ashby

И добавьте строку в `config.toml`:

```toml
boards = [
  { name = "Company", ats = "greenhouse", slug = "company" },
]
```

Если компания использует Workday, SmartRecruiters или свою систему — её так подключить нельзя, оставьте для ручного обхода. Неверный slug не ломает запуск: в логе будет ошибка по этой компании, остальное отработает.

## Что было в v3

- Помнит, куда вы уже откликнулись (через `tracker.csv`) и не показывает эти компании 30 дней.
- Отсекает вакансии с зарплатой ниже порога и поднимает те, где вилка хорошая. Зарплата видна в отчёте и Telegram.
- Отсекает гемблинг, опускает крипту и трейдинг.
- Опускает вакансии, где требуют работать по американскому времени, поднимает удобные для GMT+7.
- Сильно поднимает роли для русскоговорящих (★RU в Telegram), слегка — с китайским.
- Помечает вакансии, где упоминаются ограничения по России/Беларуси.
- Не показывает вакансии старше 14 дней.
- Присылает не больше 8 вакансий за раз, остальное в отчёте.
- По пятницам присылает недельную сводку по откликам.
- Опрашивает все источники параллельно и повторяет запрос при сбое.
- Все настройки в `config.toml`, в код лезть не нужно.

## Ежедневная работа — 30–40 минут

1. Утром приходит сообщение в Telegram.
2. Выбираете 4–5 вакансий сверху.
3. Для каждой открываете черновик в `letters/`, дописываете одно предложение о продукте компании, отправляете с резюме, указанным в шапке черновика.
4. Добавляете строку в `tracker.csv`.

## tracker.csv — единственный файл, который правите вы

```
date,company,title,status,notes
2026-09-22,Paddle,Integration Engineer,applied,
2026-09-22,Wrike,Support Engineer,reply,позвали на скрининг
```

Статусы: `applied`, `reply`, `interview`, `offer`, `rejected` (можно по-русски: отправлено, ответ, интервью, оффер, отказ). Удобнее всего редактировать прямо на GitHub с телефона: открыть файл → значок карандаша → добавить строку → Commit.

Бот этот файл только читает, поэтому конфликтов с его ежедневными коммитами не будет.

## Установка

1. Создать **приватный** репозиторий на GitHub и залить туда все файлы, включая папку `.github`.
2. Создать Telegram-бота (@BotFather), узнать chat_id, добавить секреты `TG_TOKEN` и `TG_CHAT_ID` в Settings → Secrets and variables → Actions.
3. Actions → jobwatch → Run workflow.

## Локально

```
pip install -r requirements.txt
python -m unittest discover -s tests   # проверить фильтры
python3 jobwatch.py --no-telegram      # без отправки
TG_TOKEN=... TG_CHAT_ID=... python3 jobwatch.py --test-telegram   # проверить бота
```

## Если выдача не нравится

Смотрите в конец консольного вывода или в лог Actions: там написано, сколько вакансий отсеяно и по какой причине. Если какой-то фильтр режет слишком много — ослабьте его в `config.toml`. Если в выдачу лезет мусор — добавьте слово в `title_stop` или поднимите `min_score`.

Если источник стабильно выдаёт ошибку в Actions, а локально работает — значит, он блокирует IP дата-центров GitHub. Остальные источники это не затрагивает.
